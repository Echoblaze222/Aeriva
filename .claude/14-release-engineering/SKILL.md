# AERIVA Release Engineering Skill
Before release verify versioning, release build, signing, R8/ProGuard where used, migrations, permissions, network security, crash handling, privacy disclosures, offline behavior, first run, and upgrade paths.

Never commit signing keys, passwords, tokens, service-role credentials, or secrets.

Prefer internal development, internal testing, closed testing, then production.

Document rollback/recovery where appropriate.

Release reports must include commit, build result, tests, known limitations, device validation status, migration status, and artifacts.
