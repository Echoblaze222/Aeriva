# AERIVA Documentation Standards Skill
Write for future maintainers.

Distinguish implemented, partial, planned, blocked, device-validation-required, and production-configuration-required work.

Document assumptions, platform limitations, security/privacy effects, and meaningful examples.

Avoid marketing language in engineering specs, vague claims such as "optimized", fake benchmarks, fake test results, and unexplained acronyms.

No em dash. No emojis.
